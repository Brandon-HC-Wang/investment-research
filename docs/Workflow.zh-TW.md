# 研究工作流程

## 生命週期狀態

|狀態|目的|退出條件|
|---|---|---|
| `discovery` |確定公司是否值得花時間進行研究|業務和潛在盈利機制可識別|
| `qualifying` |建立業務品質和重要性|記錄了主要部分、護城河證據和關鍵問題 |
| `active` |建立完整的因果和盈利模型|論文、情景、風險和估值在內部是一致的 |
| `monitoring` |用新證據檢驗論文 |論文條件改變或計畫深入審查到期 |
| `archived` |保留不活躍的研究 |僅在記錄了註明日期的原因後才重新開放 |

這些狀態描述的是研究成熟度，而不是投資評級。

## 新公司工作流程

1. 從 `templates/company/` 建立 `companies/<ticker>-<slug>/`。
2. 填寫 `meta.yaml` 以了解公司身分和向後相容性，然後填寫 `research.yaml` 以了解覆蓋狀態、審核時間、置信度、優先順序和觀察項目。
3. 在`01_business.md`中繪製產品、客戶、收入模式、成本結構和競爭格局。
4. 在 `02_financials.md` 中建立歷史收入、利潤、現金流量、資產負債表和股份數量基準。
5. 在 `03_growth_drivers.md` 中定義收入驅動因素、積壓或遠期指標以及替代驅動因素。
6. 在 `04_eps_model.md` 中建立基礎、上行和下行因果預測。
7. 在 `05_timeline.md` 中記錄材料日期歷史，並在 `06_notes.md` 中記錄支持觀察結果。
8. 在 `07_open_questions.md` 中建立持久的、可測試的問題。
9. 綜合 `08_thesis.md` 的論文、風險、證偽測試和置信度。
10. 在 `09_valuation.md` 中應用適當的方法和情境評估。
11. 建立假設登記冊、來源類別和第一個季度快照；更新元資料、執行驗證並檢查完整記錄是否有矛盾。

## 事件驅動程式更新

只有當事件改變證據、假設或監控時，事件才會獲得儲存庫空間。

1. 取得主要來源和日期。
2. 辨識變化的操作變數。
3. 透過收入、利潤、每股盈餘和現金流追蹤影響。
4. 將證據與目前模型和論文進行比較。
5. 以原子方式更新每個受影響的規範記錄。
6. 解決、拒絕、重新開啟或新增問題，而不刪除歷史記錄。
7. 當結論重要或可重複使用時，附加時間軸事件和研究日誌條目。
8. 更新 `last_update`、`next_action`、監視專案、信心和優先順序（如有保證）。

## 定期審查

對於季度或年度業績：

1. 將報告的營運驅動因素與先前的假設進行比較。
2. 核對報告的每股盈餘和標準化的每股盈餘。
3. 解釋收入和利潤差異，而不是列出結果。
4. 評估積壓或領先指標以及替代驅動程式。
5. 僅在保留先前的預測快照後滾動預測年份。
6. 重新測試下行機制和資產負債表彈性。
7. 評估前重新評估論文。
8. 設定下一次審核觸發器。

## 搜尋策略與 screen 工作流程

1. 在 `strategies/` 定義可測試經濟機制、確認與否證訊號、時間範圍及驗證門檻。
2. 在 `screens/` 定義可重現母體、條件、排序、警示旗標、來源階級、輸出欄位及刷新政策。
3. 登錄兩個 definitions，並保持雙向引用一致。
4. 刷新前先執行本機到期檢查，並確認使用者已明確要求連線或執行。
5. 建立新的時間戳記 run，不得覆寫先前 manifest 或結果。
6. 記錄 definition version、來源與資料日期、覆蓋率、備援來源、失敗、參數及限制。
7. 只在 run 結果確定後更新可重建 screen state。失敗 run 不得推進最後成功時間。
8. 只有重大跨 run 結論才加入 `research-log/`；個別公司則須經人工審查後才能加入 coverage。

Strategy 驗證階段為 `idea`、`testing`、`validated`、`monitoring`、`rejected` 及 `archived`。Screen 刷新狀態為 `fresh`、`due`、`overdue`、`blocked` 及 `disabled`。兩種生命週期都不是投資評級。

## 矛盾處理

當可信證據發生衝突時：

- 保留聲明及其來源；
- 確定定義、時期、激勵措施或範圍方面的差異；
- 若衝突嚴重，則降低信心；
- 增加一個有解決方法的開放式問題；
- 不要僅僅為了讓文件看起來一致而強行得出結論。

## 完成標準當規範文件同步、歷史記錄被保留、證據被引用、不確定性明確、下一步操作可執行、可重用的結果被提升並且 `scripts/validate_repository.py` 通過時，更改就完成了。
