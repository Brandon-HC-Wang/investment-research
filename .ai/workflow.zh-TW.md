# AI 改變工作流程

<!-- 衍生繁體中文閱讀版；英文原檔 `workflow.md` 是唯一 canonical source。若內容衝突，以英文版為準。 -->

## 1. 載入上下文

按順序閱讀所需的四個文件。對於公司變更，載入元資料、論文、開放式問題、所有相關編號記錄、產業指南和模型約定。

## 2. 將輸入分類

確定新材料是否：

- 來源事實；
- 管理索賠；
- 分析師估計；
- 新的或改變的假設；
- 先前研究的修正；
- 方法或系統的改變。

不要將新聞稿視為分析。僅提取改變因果模型或縮小證據差距的內容。

## 3.繪製影響圖

透過以下方式追蹤新資訊：

`operating variable → revenue → margin → operating profit → below-the-line items → share count → EPS → cash flow → thesis/valuation`

標記無關緊要或未知的階段。不要假設收入變化與每股收益成比例。

## 4. 原子更新

透過一次連貫的編輯更改所有受影響的規範文件。保留 `assumptions.md` 中的舊假設和註明日期的歷史記錄、更新目前摘要以及新增或變更未決問題狀態。更新 `research.yaml` 的工作流程狀態，同時保留 `meta.yaml` 中的向後相容字段，直到遷移完成。

## 5.記錄出處

將源元資料附加在其支援的聲明附近，並在適當的 `sources/` 類別下保留合法工件。如果發現結果可在公司之間重複使用，請將其新增至產業包、知識層、論文或範圍研究日誌中，並連結回公司記錄。

## 6. 質疑結論

尋找反對新興觀點的證據。測試替代解釋，確定對 EPS 最敏感的不確定性，並將真正的結構性變化與時間、組合、會計或週期效應區分開來。

## 7. 驗證

運行：

```bash
python3 scripts/validate_repository.py
```

檢查差異是否存在意外歷史刪除、日期不一致、連結斷開、未引用的重要事實以及 EPS 模型、論文、評估和元資料之間的矛盾。

## 8. 切換

總結哪些規範記錄發生了變化、最重要的結論、剩餘的不確定性以及下一步。不要提出建議。
