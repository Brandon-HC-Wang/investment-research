## 2026-10-12 — Confirmed interval qualification rule

**Owner decision:** a range such as **6.42%–7.41%** counts as meeting the **7%** base-yield gate. Definition version **4** uses the unrounded upper bound inclusively: `upper >= target`. If `lower < target <= upper`, label `partial_range`; if `target <= lower <= upper`, label `entire_range`. Both satisfy this one criterion; a point below the target does not reject an otherwise supported interval. This supersedes the earlier requirement to judge the base-yield gate by the representative point alone. No probability is implied by interval overlap.

Applied to the prior earnings-to-payout sensitivity, using the **2026-10-08** reference prices: **3213, 6.42%–7.41%, qualifies for the base-yield criterion as partial_range**; **5515, 4.93%–5.69%, does not qualify for that criterion**. These remain unvalidated cash-allocation sensitivities; this classification does not establish a fully qualified company candidate. Required EPS coverage **1.25×**, downside yield **5%**, input coverage **95%**, parent cash evidence and remaining sector-model gaps are unchanged. PILOT-Q-001/PILOT-Q-002 remain Open.

Implementation records actual DPS lower/upper inputs, representative values and yield bounds, validates non-negative ordered intervals, and distinguishes the two qualification labels. Partial-range results carry a review flag. Filtering uses raw arithmetic: an upper bound below **7%** cannot qualify merely because display rounding shows **7.00%**. Bounds must be analytically evidenced, not widened to meet the filter.

The first pilot and its inputs remain unchanged under version **3**. The exact old definition is archived and new executions retain an immutable definition snapshot; validation uses each run's own version/hash/header. The registered state is due under version **4**, with no successful new run. Boundary, invalid-input, independent-gate and historical-artifact tests verify software behavior; they do not validate forecasts or strategy performance. This change did not create an additional formal company run or update company forecasts.

Validation on 2026-10-12: all 44 offline unit tests passed; repository validation, bilingual numeric parity and original pilot input checksums passed. Software verification is separate from dividend forecast validation.
